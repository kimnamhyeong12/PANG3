# 클라이언트 주기 조회 확인

현재 저장소의 웹·앱 실행 코드를 확인했다. 실행 로그를 이용한 운영 트래픽 측정은 포함하지 않는다. 조회 방식은 이번 감사에서 변경하지 않았다.

| 구분 | 조건·간격 | 서버 요청 |
| --- | --- | --- |
| 업무 목록 | 방문지·그룹·프로젝트·보고서·문의·시설물 신청 목록의 15초/30초 반복 조회 타이머 없음 | 진입·수동 새로고침·저장 또는 변경 알림에 따른 조회 |
| 웹 소셜 계정 인증/연결 | 인증 중 1.5초 간격, 최대 5분 | `/api/auth/social/poll` |
| 앱 소셜 로그인/인증/연결 | 인증 중 1.5초 간격, 최대 5분 | `/api/auth/social/poll` |
| 변경 알림 재연결 | 끊겼을 때 1초부터 최대 30초까지 재시도 | `/api/sync/events` 재연결 성공 후 `resync`에 따라 현재 화면·계정 및 방문지 캐시 재조회 가능 |
| 로그인 토큰 만료 | 기본 900초, 설정으로 변경 가능 | 스트림은 인증 만료 시 닫히므로 재연결과 누락 변경 확인용 재조회가 생길 수 있음. 업무 데이터가 전혀 바뀌지 않아도 발생 가능 |
| 웹 지도 날짜 확인 | 30초마다 | 날짜 문자열만 확인. 같은 날짜이면 서버 조회 없음 |
| 앱 오늘 날짜 확인 | App·그룹 대시보드·업무현황에서 60초마다 | 날짜 문자열만 확인. 같은 날짜이면 서버 조회 없음. 날짜가 바뀌면 오늘 업무 재계산·관련 갱신 가능 |
| 앱 길안내 표시 | 안내 중 6초마다 | 표시 문구 전환만 하며 서버 조회 없음 |
| 서버 스트림 생존 신호 | 25초마다 | 기존 연결에 주석만 전송. DB 조회 없음. 토큰 만료도 이때 확인 |

탭을 다시 보이게 하거나 앱을 전면으로 돌아오게 하면 스트림이 재연결되므로 그때도 `resync` 조회가 가능하다. 65초 동안 생존 신호조차 없으면 연결이 끊긴 것으로 간주한다. 토큰 갱신 자체는 별도 정기 타이머가 아니라 요청 직전의 만료 확인으로 수행한다.

검색어 입력·지도 좌표 이동 후의 0.25~0.35초 지연 조회, 경로 추천 요청의 짧은 지연, 길안내 복구 실패 시 5초 뒤 제한된 재시도, 요청 시간 제한은 상시 목록 주기 조회와 구분한다. 사진/보고서 임시 입력 저장은 로컬 저장이다.

서버에는 알림 발송(매일 09:00·17:00), 공휴일 캐시(매월 1일 02:10), 보존기간 정리 등 예약 작업도 있다. 이는 클라이언트 목록을 일정 간격으로 다시 불러오는 동작이 아니다.

주요 근거: `web/src/components/SocialAccounts.jsx`, `frontend/utils/socialAuth.js`, `frontend/utils/changeSync.js`, `web/src/components/useLiveRevision.js`, `web/src/context/AuthContext.jsx`, `backend/src/main/java/com/fieldwork/sync/ChangeHub.java`, `backend/src/main/java/com/fieldwork/service/AuthSessionService.java`.
