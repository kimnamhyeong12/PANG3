# 근무지역 선택 규칙

적용: 회원가입·계정 관리·그룹 생성·그룹 활동지역 변경·지도·업무현황. 2026-10-22 수정, 서버 배포 필요.

## 화면 동작

- 최초에는 시·도와 시·군·구 두 칸을 표시하고 모두 ‘선택해주세요’로 시작한다.
- 시·도를 선택해야 두 번째 칸을 사용할 수 있다.
- 부산광역시 → 사하구, 충청남도 → 아산시처럼 하위 구가 없는 지역은 두 칸으로 끝난다.
- 충청남도 → 천안시처럼 하위 일반구가 있는 시는 세 번째 ‘구’ 선택칸을 표시한다.
- 세 번째 칸이 표시되면 구까지 선택해야 회원가입/계정 저장을 할 수 있다.
- 시·도를 바꾸면 두 번째·세 번째 선택을 지운다. 시·군·구를 바꾸면 기존 구 선택을 지운다.
- 행정동은 가입/계정 관리에서 받지 않는다. 근무지 상세 주소도 선택사항이다.

## 전국 자료

행정안전부 2026-09 통계에 나온 시군구 이름으로 구성했다. 하위 일반구가 있는 13개 시·39개 구를 포함한다: 수원·성남·안양·부천·안산·고양·용인·화성·청주·천안·전주·포항·창원.

출처: [행정안전부 주민등록 인구통계](https://jumin.mois.go.kr/ageStatMonth.do)의 전국 시군구 CSV 및 지역 선택 목록. 원본은 `backend/target/national-regions-full.csv`, 선택용 스냅샷은 앱/서버의 `korea-regions.json`에 동일하게 반영했다. 통계 코드와 SGIS 코드는 다른 체계이므로 혼용하지 않는다.

## 저장과 호환

DB 컬럼은 추가하지 않는다. `workSido`에는 충청남도, `workSigungu`에는 ‘천안시 동남구’를 저장한다. 부산은 기존처럼 ‘사하구’다. 개인 공간은 기존 근무지역 연결을 그대로 사용한다.

계정 관리에 들어갈 때 저장 문자열을 다시 시/구로 분리한다. 기존 ‘천안시’만 저장한 계정은 구가 미선택으로 나오며 저장 전에 선택한다. 상위 지역 변경 시 이전 구가 새 지역에 섞이지 않는다. 구 광주·전남, 강원도·전라북도 이름은 현재 선택 이름으로 해석하되 DB를 일괄 수정하지 않는다.

서버도 같은 자료로 시·군·구와 필수 하위 구를 검사한다. 다른 지역의 구나 시 이름만 전송한 잘못된 요청은 거부한다. 앱과 서버 자료의 일치는 회귀 테스트로 확인한다.

## 범위와 확인

그룹 생성·지역 변경도 같은 전국 선택 목록을 쓴다. `/api/sgis/boundaries/by-region`에서 선택한 시·군·구의 행정동을 조회하며 모바일 지도·업무현황과 웹 지도가 이를 공유한다. `천안시동남구`와 `천안시 동남구`의 표기 차이, 세종의 시·군·구 단계도 처리한다. 지역이 없을 때 사하구로 대체하지 않는다. 공공시설물 데이터의 전국 수집은 제외한다. 외부 SGIS 데이터의 경계 연도와 지역별 실제 조회는 별도 확인이 필요하다.

부산 출입구 좌표의 경로 적용과 배포 파일 검사는 제거했다. 데이터 파일은 보관하며 되돌리기용 패치는 `tmp/entrance-removal.patch`에 남긴다.

새 보고서 사진·위치도는 앱에서 JPG 품질 0.7로 전송하고 서버도 JPG 품질 0.7로 저장한다. 서버 저장 시 긴 변 1920 이하로 디코딩해 메모리 사용을 제한한다. 업로드의 Python WebP 변환과 Java WebP 디코더 의존성은 제거했다. HWPX·HTML·서버 정적 위치도도 JPEG 품질 70을 사용한다. 사용자 요청에 따라 서버 시작 시 기존 WebP 사진·위치도와 DB 연결, 해당 보고서 캐시 및 WebP가 들어간 HWPX 캐시를 삭제한다. JPG·PNG 원본과 보고서의 제목·메모·작업상태는 유지한다. 신규 WebP 업로드는 받지 않으므로 앱의 변경된 사진 업로드 코드도 함께 적용해야 한다.

이전 검증 이력: 부산 2단계/천안 3단계/아산으로 변경 시 구 제거/시·도 변경 초기화/전국 지역 저장·복구/서버 필수 구 거부/주소 없는 가입 및 계정 수정. 이번 변경은 요청에 따라 기능 테스트 없이 서버 컴파일과 문법만 확인했다. 실기기 및 AWS 적용은 별도 확인한다.
