# 공공시설물 등록 신청 / 그룹 초대 링크

## 앱

공공데이터 카테고리 AED·버스정류장 아래 **공공시설물 등록 신청**에서 신청과 내 신청 내역을 확인한다.

필수: 시설물 이름, 시설 종류, 현재 위치 지도 스크린샷, 시설물 원본 사진, 상세 위치, 확인 날짜, 사진·촬영 위치정보 수집 동의. 추가 설명은 선택이다. 확인 날짜는 기존 달력 컴포넌트로 선택한다.

사진은 각 15MB 이하 JPG/PNG만 받는다. 시설물 사진 선택 즉시 기존 원본 사진 접근 권한과 메타데이터 추출 절차로 GPS를 읽어 지도·좌표·역지오코딩 주소를 표시한다. GPS가 없으면 접수하지 않으며 현재 기기 위치로 대체하지 않는다. Android Expo Go는 원본 GPS 제한이 있으므로 개발용 네이티브 빌드에서 확인해야 한다. HEIC는 현재 지원하지 않는다.

서버는 클라이언트 좌표를 신뢰하지 않고 원본 이미지 EXIF에서 GPS를 다시 추출한다. 이미지는 크기 검증 및 JPEG 재인코딩 후 보관하며 EXIF는 제거한다. 추출 좌표는 신청 DB에 보관한다. GPS 메타데이터 자체는 편집 가능하므로 사진과 스크린샷을 사람이 함께 검토해야 한다.

## 관리자

웹 `/admin/facilities`에 `ADMIN` 또는 `FACILITY_REVIEWER` 역할로 접속한다. DB 역할 부여는 이번 변경에서 실행하지 않았다. 기존 문의 답변 전용 `SUPPORT_AGENT`는 시설 검토 권한이 없다.

처리: 접수 → 검토 중 / 보완 요청 / 반려 / 승인. 승인·반려 후 재처리는 막는다. 보완 요청은 사유 열람까지 지원하며 기존 신청 수정·추가 답변 기능은 없다. 사용자는 수정 내용을 담아 새로 신청할 수 있다.

승인 시 최종 이름, 주소, 좌표, 시·도, 시·군·구, 행정동, 등록 카테고리를 확인한다. 행정동은 기존 공공데이터 필터와 정확히 일치해야 검색된다. 카테고리에 AED·심폐제세동기·자동심장충격기는 `aed`, 버스정류장은 `bus`로 합쳐지고 다른 이름은 새 카테고리를 생성한다. 승인 데이터만 지역별 공공데이터 응답에 추가한다. 기존 공식 AED·버스정류장 원본은 수정하지 않는다. 자체 등록 항목은 기존 ID와 충돌하지 않도록 음수 ID로 반환한다.

동시 검토 시 버전 확인과 DB 잠금으로 중복 승인을 막는다. 신청자만 자기 신청을 볼 수 있고 검토 권한자만 전체 신청과 증빙을 조회한다. 증빙은 공개 URL이 없으며 인증 다운로드 API를 사용한다. 신청자 정보와 증빙 사진은 공공데이터로 공개하지 않는다.

### API

- `GET /api/public-data/categories`: 기본 + 등록 카테고리
- `POST /api/facility-applications`: multipart `application` JSON, `photo`, `screenshot`
- `GET /api/facility-applications?page=0`, `GET /api/facility-applications/{id}`: 본인 신청
- `GET /api/admin/facility-applications?page=0`, `GET /api/admin/facility-applications/{id}`: 관리자 신청함
- `POST /api/admin/facility-applications/{id}/review`: 상태·검토 사유·버전·최종 등록 정보
- `GET /api/[admin/]facility-applications/{id}/evidence/{photo|screenshot}`: 증빙 JPEG

## 그룹 초대

그룹 업무공간의 팀원 영역에서 **초대 링크 공유**를 누르면 OS 공유창을 연다. 기존 ID 초대는 유지된다. 개인 업무공간은 링크를 발급하지 않는다.

형식: `https://pinwork.co.kr/join/{token}`. 무작위 256비트 토큰은 DB에 SHA-256 해시만 보관한다. 발급 후 7일, 신규 참여 최대 50명. 발급자 또는 그룹장이 링크를 중지할 수 있다. 발급자가 탈퇴한 링크는 사용할 수 없다. 링크를 가진 사람은 로그인 후 참여할 수 있으므로 공개 범위를 확인해 공유한다.

링크 열기만으로 가입시키지 않는다. 앱의 `pang3://join?token=...` 처리와 웹 `/join/:token` 화면에서 그룹 이름을 확인하고 **참여하기**를 눌러야 한다. 로그아웃 상태로 앱을 열어도 초대 토큰을 유지해 로그인 후 확인한다. 동일 사용자 중복 참여는 새 멤버를 만들지 않는다.

- `POST /api/groups/{groupId}/invite-links`: 멤버가 링크 발급
- `GET /api/group-invite-links/{token}`: 로그인 후 초대 미리보기
- `POST /api/group-invite-links/{token}/join`: 명시적 가입
- `DELETE /api/group-invite-links/{id}`: 발급자 또는 그룹장이 중지
- `GET /join/{token}`: 비로그인 브라우저용 앱 열기 안내 (그룹 정보 비공개)

## 배포 시 필요한 작업 (아직 실행하지 않음)

1. `backend/sql/2026-10-29-facility-invites.sql` 검토·적용 후 새 백엔드 배포. 개발 환경 Hibernate 자동 갱신만 운영 마이그레이션 대신으로 간주하지 않는다.
2. 업로드 디렉터리 `facility-evidence/`를 영구 볼륨에 두고 정적 공개 경로에서 제외한다. 기존 업로드 제한(사용자/전체 보관량)을 사용한다. 이미지 보관의 자동 파기 작업은 이번 구현에 포함되지 않는다.
3. 검토할 계정에 필요한 DB 역할을 부여한다. 계정 지정은 별도 작업이다.
4. `pinwork.co.kr` HTTPS와 프록시가 신규 `/api/...` 및 `/join/...`를 전달하도록 설정한다. `/join/...`는 배포된 웹 SPA로 보내면 웹 참여까지 지원하고, 백엔드로 보내면 앱 열기 안내를 제공한다. 기존 OAuth 콜백 경로를 유지한다. 실제 도메인 프록시는 이번 작업에서 변경하지 않았다.
5. 네이티브 앱은 기존 `pang3` 스킴을 사용한다. HTTPS Android App Links/iOS Universal Links 자동 실행용 도메인 검증 파일은 추가하지 않았다. 브라우저에서 **핀워크 앱에서 열기**를 누르는 흐름이다.
6. 실제 휴대폰 원본 GPS 사진 두 장 첨부 → 관리자 검토·승인 → 해당 행정동 지도 조회, 다른 사용자 초대 링크 참여까지 운영 환경에서 확인한다.
