# 출시 준비 1차: 인증·자동 로그인·이메일 복구

> 보관 문서: 작성 당시의 조사·변경 기록입니다. 현재 구현·검증 상태는 [문서 목차](../../README.md)에서 관련 문서를 확인하세요. 아래 작업 지시는 이 기록을 열었다는 이유로 실행하지 않습니다.

브랜치: `codex/app-release`. 같은 앱의 코드를 수정했다. 별도 출시용 앱 프로젝트를 복제한 작업이 아니다. 운영 서버, AWS, 카카오 콘솔, EAS 자격 증명, Google Play는 변경하지 않았고 실제 사용자 데이터도 수정하지 않았다.

## 구현한 동작

- 로그인 시 256비트 무작위 access/refresh 토큰을 발급하고 DB에는 SHA-256 해시만 저장한다. JWT 대신 DB 세션을 사용해 로그아웃·탈퇴·비밀번호 재설정 시 접근을 해제할 수 있게 했다.
- access 토큰은 기본 15분, 로그인 유지 기간은 마지막 갱신부터 기본 90일이다. 사용 중에는 자동 갱신하며 앱을 다시 열어도 refresh 토큰으로 복원한다. 네트워크 장애는 유지 정보를 삭제하지 않고 다시 연결할 수 있게 한다.
- 모바일 refresh 토큰은 Expo SecureStore에 저장한다. access 토큰은 메모리에만 보관한다. 웹 refresh 토큰은 HttpOnly/Secure/SameSite=Lax 쿠키, access 토큰은 메모리로 관리한다. 기존 웹의 로컬 사용자 정보만으로 로그인된 것으로 판단하던 처리를 제거했다.
- refresh 토큰은 중단된 응답·동시 요청으로 로그인 유지가 끊어지는 일을 줄이기 위해 세션 동안 유지하며 access 토큰을 교체한다. refresh 토큰 회전·재사용 탐지 방식은 이번에 적용하지 않았다.
- 공개 로그인·가입·메일 링크 처리 외 `/api/**` 요청은 인증해야 한다. 사용자·생성자·초대자·이관 요청자 등 요청의 ID는 로그인한 사용자와 비교한다. 이관받는 사람 등 업무 대상 ID는 그대로 유지한다.
- 그룹의 업무·보고서는 그룹 멤버 누구나 조회할 수 있다. 담당자만 기록·상태·일정·삭제를 변경하는 기존 업무 규칙을 보호했다. 기존 레거시 관리 API의 역할 모델을 전면 재설계한 작업은 아니다.
- 사진 조회, 보고서 조회·준비·개별/통합 다운로드의 접근을 확인한다. 회원가입 응답에서 비밀번호 해시를 제외한다.
- 사진 편집은 인증해서 받은 임시 로컬 파일을 사용한다. 보고서는 인증 다운로드 후 기기의 공유/열기 기능으로 전달한다. 토큰을 파일 URL에 붙이지 않는다.
- JSON 보고서의 사진 경로는 해당 업무의 저장 폴더에 있는 실제 파일만 허용한다. 업로드 확장자를 JPG/JPEG/PNG/WEBP로 제한하고 파일 조회 시 경로·심볼릭 링크 경계도 검사한다. 실제 파일 내용·이미지 크기의 전체 검증은 추가 출시 작업이다.
- 이메일 등록/변경은 현재 비밀번호 확인 후 새 주소에 인증 메일을 보낸다. 인증한 이메일만 비밀번호 복구에 사용한다. 기존 사용자는 설정에서 등록할 수 있고 신규 가입에는 선택 이메일 입력을 추가했다.
- 인증·재설정 링크는 기본 30분, 1회만 사용한다. DB에는 토큰 해시를 저장하며 비밀번호 재설정 시 기존 세션과 관련 링크를 무효화한다. 링크는 웹 페이지의 URL fragment로 전달하고 페이지에서 제거한다.
- 로그인·가입·이메일 요청 등에 IP별 5분 30회 제한을 추가했다. 단일 서버의 메모리 제한이며 다중 서버 운영에서는 게이트웨이/공유 저장소 제한을 추가해야 한다.
- CORS 와일드카드를 제거하고 명시한 웹 origin만 허용한다.

## 검증

- Spring MVC + Spring Security + 실제 JPA/H2 테스트 DB를 사용한 인증 통합 테스트 8개: 미인증/위조 토큰, 사용자 ID 위조, 만료·갱신·로그아웃, 타 계정 탈퇴 차단, 일반 그룹 멤버 조회, 비담당자 수정 차단, 외부 그룹 사진·보고서 차단, 웹 쿠키/CORS, 회원가입 응답, 이메일 인증·재설정·일회 사용, 요청 제한.
- 파일 격리 테스트 1개: 다른 업무 파일·file URI·없는 파일·비허용 업로드 확장자 차단.
- 프론트 기존 회귀 검증 12개, 사진 편집 검증 1개, 새 세션 수명주기 검증 1개 통과. 새 세션 검증은 동시 401의 단일 갱신, 외부 제공자로 토큰을 보내지 않음, 오프라인 유지, 무효화, 갱신 도중 로그아웃을 다룬다.
- 기존 Java assertions 계약 검증 5개 통과. 인증이 필요한 컨트롤러를 직접 호출하는 기존 검증에는 로그인 사용자 fixture를 추가했다.
- 웹 production 빌드 성공.
- Android JS/Hermes export 성공: 958 모듈.
- SecureStore가 포함된 Android arm64 debug APK 네이티브 빌드 성공. 새 AndroidX biometric 의존성을 내려받았다. 기존 SDK/React Native/Gradle 버전은 유지했다.
- `git diff --check` 확인.

H2 테스트는 운영 PostgreSQL 마이그레이션 검증을 대신하지 않는다. Android debug 빌드는 정식 서명 AAB나 실기기 동작 검증을 대신하지 않는다. 실제 이메일은 보내지 않고 테스트 MailSender를 사용했다. iOS 네이티브 빌드·실주행·운영 E2E는 수행하지 않았다.

## AWS 담당 팀원에게 전달할 설정

1. 검증 환경과 DB 백업을 준비한다.
2. `backend/sql/auth_release_migration.sql`을 검토하고 PostgreSQL 검증 환경에서 적용한다. users.email, auth_sessions, email_challenges가 추가된다. 운영 데이터 삭제는 포함하지 않는다.
3. 검증 환경의 새 백엔드와 새 앱을 함께 사용한다. 기존 앱에는 인증 토큰이 없으므로 새 서버 적용 후 API를 사용할 수 없다. 구버전 사용자 대응과 배포 시점을 함께 정해야 한다.
4. HTTPS로 웹과 API를 제공한다. 웹은 같은 origin의 `/api` 프록시 사용을 권장한다. 서로 다른 사이트에 웹/API를 배포하면 현재 SameSite=Lax 쿠키 정책에 맞는 구성을 별도 확인해야 한다.
5. `release` Spring profile과 다음 값을 환경 또는 SSM 기반 설정으로 제공한다. 비밀번호·SMTP 자격 증명은 Git/채팅에 기록하지 않는다.

| 값 | 내용 |
|---|---|
| SPRING_PROFILES_ACTIVE | release |
| FIELDWORK_AUTH_ALLOWED_ORIGINS | 실제 웹 origin. 복수는 쉼표 구분, 와일드카드 불가 |
| FIELDWORK_AUTH_PUBLIC_URL | 인증/재설정 페이지를 제공하는 HTTPS 웹 주소 |
| FIELDWORK_AUTH_MAIL_FROM | 인증된 발신 이메일 |
| SMTP_HOST / SMTP_PORT | 메일 발송 서버와 포트, 기본 587/STARTTLS |
| SMTP_USERNAME / SMTP_PASSWORD | 발송 서비스 자격 증명 |

메일 설정이 없으면 이메일 기능은 503과 준비되지 않았다는 안내를 반환한다. 이메일 없는 기존 계정 로그인 및 선택 이메일 없이 가입하는 것은 가능하다. 선택 이메일을 넣은 신규 가입 중 메일 발송이 실패하면 트랜잭션을 롤백하도록 했다.

현재 토큰은 불투명한 무작위 DB 세션이므로 JWT 서명용 비밀키는 추가로 필요하지 않다. DB와 TLS, 기기 저장소 보안은 필요하다. 로컬 HTTP 웹 테스트에서는 검증 환경에 한해 `fieldwork.auth.cookie-secure=false`를 명시해야 하며 출시에서는 true를 유지한다.

## 사용자님에게 필요한 준비

- 비밀번호 복구 메일을 보낼 서비스와 발신 주소 결정.
- 인증/재설정 페이지를 공개할 웹 주소 준비. 새 web/ 빌드의 `/verify-email`, `/reset-password`, `/forgot-password`를 제공하고 SPA 새로고침 fallback을 설정해야 한다.
- 검증 환경이 연결된 후 실제 휴대폰에서 최초 로그인 → 앱 종료/재실행 → 사진 보기/편집 → 보고서 열기 → 로그아웃을 확인.
- 실제 테스트 계정으로 이메일 수신·만료·재설정·이전 비밀번호 로그인 실패 확인.
