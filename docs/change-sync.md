# 앱·웹 변경 동기화

방문지의 웹 15초·앱 팀 공간 30초 반복 조회와 앱 길안내 요청 15초 조회를 변경 알림으로 대체한다. 개인·팀 공간 모두 같은 동기화 규칙을 사용한다.

## 저장과 전송

- `/api/sync/events`: 로그인한 앱·웹마다 활성 상태에서 SSE 연결 하나를 유지한다. 숨겨진 탭·백그라운드 앱은 연결을 중단한다.
- Hibernate 영속화 이벤트가 변경 종류와 관련 사용자·그룹·방문지 ID만 수집한다. 입력 중인 폼, 비밀번호, 보고서 내용, 사진은 알림에 포함하지 않는다.
- PostgreSQL에서는 실제 데이터와 `sync_changes` 알림 기록을 **같은 트랜잭션**으로 저장하고 `pg_notify`로 기록 ID를 보낸다. DB는 커밋 후에만 알림을 전달한다. 같은 트랜잭션의 알림은 합쳐지며 여러 API 프로세스도 같은 DB 알림을 받는다.
- 알림 기록 저장 자체가 실패하면 방문지 저장도 롤백된다. 저장 성공으로 응답하고 알림 기록을 잃는 별도 저장 단계를 두지 않는다.
- 커밋 이후 브라우저 연결이 끊기거나 변경 조회가 실패해도 저장한 방문지는 남는다. 연결 복구 시 최신 데이터를 다시 확인하며 등록 POST를 자동 재전송하지 않는다.

## 갱신 범위와 캐시

- 방문지 변경은 `/api/sync/tasks?groupId=...&ids=...`로 변경된 ID만 조회한다. 앱·웹의 기존 목록에 병합하고 삭제·담당자 이동을 반영한다. 그룹 구성·대량 변경은 해당 목록을 무효화한다.
- 앱의 전체 그룹 방문지와 내 배정 목록, 웹 그룹 방문지 조회는 세션 안의 목록 캐시를 재사용한다. 등록 성공 응답도 캐시에 병합한다. 첫 조회와 변경 알림이 겹치면 오래된 응답이 변경을 덮어쓰지 않도록 재확인한다.
- 업무 상태·이관·보고서·프로젝트·그룹·계정·알림 설정·문의·시설물 신청/승인은 해당 화면의 조회만 갱신한다. 편집 중인 폼은 유지하고 충돌 안내를 표시한다. 기존 보고서 저장의 버전 검사는 유지한다.
- 새 연결·장애 복구·포그라운드 복귀 시 `resync`를 보내 누락된 삭제와 추가도 복구한다. 실패 시 재연결 간격은 최대 30초까지 늘어난다. 변경 없는 정상 연결에는 목록 재조회 타이머가 없다.
- 25초 keep-alive는 연결 유지용 주석이며 DB 조회를 하지 않는다. 알림 기록 정리는 시간당 1회, 하루 지난 기록만 대상으로 한다. 이는 방문지 반복 조회와 별개다.
- 세션 만료·철회 또는 계정 삭제 시 스트림을 종료한다. 토큰 회전 때문에 정상 스트림을 주기적으로 끊고 목록을 다시 읽지는 않는다.

## 검증

- 서버: 커밋/롤백, 그룹 권한, 이전·새 그룹 동시 통지, 삭제/이동 delta, 알림 기록 장애 시 저장 롤백, 세션 철회.
- 공유 JS: 목록 재사용, 변경 병합, 중복 이벤트, 담당자 이동, 초기 응답 경합, 로그아웃 경합, 오류 재연결, 로컬 저장 응답 재사용.
- Chromium: 변경 ID만 조회, 61초 무변경 시 목록 요청 없음, 연결 중단 동안 발생한 변경 복구, delta와 복구 조회 연속 실패 후 복구, 입력 중인 방문지 폼 유지.
- Android 실제 단말 및 실제 PostgreSQL 다중 프로세스 부하 검증은 별도로 필요하다. 기존 설치 앱에는 새 앱 빌드를 설치해야 적용된다.

PostgreSQL 동작 근거: [NOTIFY](https://www.postgresql.org/docs/current/sql-notify.html), [pgJDBC PGConnection](https://jdbc.postgresql.org/documentation/publicapi/org/postgresql/PGConnection.html).

## SSE 연결 점유 결함 수정

기존 구현은 기본 Open EntityManager in View가 SSE 요청에도 적용되어, 열린 스트림마다 JDBC 연결을 유지했다. 여러 탭·앱 연결이 쌓이면 풀의 연결이 부족해 일반 목록·상세 요청이 대기하다 실패할 수 있었다. `JpaViewConfig`에서 SSE 경로만 제외하고 다른 MVC 경로의 기존 JPA 범위는 유지한다. 정상 SSE 종료의 ASYNC 디스패치는 최초 요청의 인증을 다시 요구하지 않도록 해당 경로에 한정해 허용한다.

실제 내장 Tomcat과 HTTP 클라이언트, DB 풀 2개로 검증한다. 수정 전에는 스트림 1개가 DB 연결 1개를 계속 점유하는 것을 재현했다. 수정 후에는 스트림 4개가 열려 있어도 DB 연결 점유가 0개이며 시설물 목록을 조회할 수 있다. 일반 MVC 경로의 Open in View 유지도 검사한다.

개별 화면의 GET 실패는 건강한 전체 변경 알림 연결을 재시작하지 않는다. 방문지 delta/초기 스냅샷의 복구 처리는 유지한다. 문의함·시설물 신청함은 화면 전환 시 진행 중인 요청을 취소하고 목록/상세 조회를 20초로 제한한다. 실패를 빈 목록이나 선택 전 화면으로 표시하지 않으며 선택·기존 데이터·작성 중 내용은 유지한다.
