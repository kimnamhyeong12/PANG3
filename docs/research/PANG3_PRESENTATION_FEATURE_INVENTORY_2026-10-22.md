# PANG3 발표 기능 전체 목록 — 코드 기준

분석일: 2026-10-22. 발표에 넣을 내용을 사용자가 먼저 고르기 위한 기능 목록이다. **목록의 항목 수는 PPT 페이지 수가 아니다.** 중요도나 페이지 배분은 아직 확정하지 않는다.

## 조사 범위와 읽는 방법

- 앱 진입점 `frontend/App.js`, 앱 화면·컴포넌트·유틸리티·알림 서비스·Android 네이티브 모듈을 확인했다.
- 웹 진입점 `web/src/App.jsx`, 실제 라우트의 화면과 API 호출을 확인했다.
- 관련 백엔드 controller·service·entity와 Python 건별/통합 보고서 생성 코드를 대조했다.
- 문서나 파일명에만 있는 기능이 현재 앱 메뉴·웹 라우트·서버 API에 연결돼 있는지 구분했다. 과거 화면·백업·테스트 파일·라이브러리 파일은 별도 제품 기능으로 세지 않았다.
- 이번 작업은 **소스 분석**이다. 앱 재실행·실주행·운영 서버 접속·외부 키 확인·전체 테스트 재실행을 하지 않았다. ‘연결’은 사용자 동작과 처리 코드가 연결됐다는 뜻이며, 실제 배포 환경에서 검증을 마쳤다는 뜻이 아니다.

| 상태 | 의미 |
|---|---|
| 연결 | 현재 화면과 관련 처리 코드에서 구현 연결 확인 |
| 조건 | 구현은 있으나 특정 기기·운영 설정·외부 서비스·데이터가 필요 |
| 서버 | 서버 처리 코드는 있으나 현재 일반 화면에서 실행 진입을 확인하지 못함 |
| 보류 | 비활성·미연결·자리 표시·기존 코드로 현재 발표 기능에서 제외 |

기본 지도·공공데이터도 실제 API 키와 적재 데이터가 있어야 작동한다. ‘조건’은 특별히 플랫폼 제한이나 공급자 인증·발송 설정 등이 발표 설명에 영향을 주는 경우 표시했다.

## 판단할 때 사용할 기능 묶음

기존에 사용자가 강조한 여섯 핵심은 유지하면서, 빠진 기능을 아래 후보에서 선택한다. 아직 장표 수는 정하지 않는다.

1. **좌표 기반 지점 지정·위치 정정** — 주소로 구분하기 어려운 작업 지점.
2. **공공데이터 활용** — AED·버스정류장을 업무로 연결.
3. **Excel·CSV 일괄 등록** — 열 매핑·검증·오류 파일까지.
4. **사진 GPS 기반 등록** — 지점 생성과 작업 전 사진 연결.
5. **경로 추천과 자유로운 방문 선택** — 완료 후 재추천·복귀 포함.
6. **차량 내비·도보 이동 지원** — 실제 안내와 지도 탐색 편의.
7. **전·중·후 현장 기록** — 상태·완료 시각·제목.
8. **사진 편집** — 펜·크롭·회전·이력.
9. **위치도 작성·표시** — 현장 사진과 별도인 지도 기록.
10. **음성 메모·초안 복구** — 현장 입력 편의.
11. **그룹 현황·협업** — 담당·상태·행정동 시각화.
    - 별도 분석 화면 후보: 완료율·월간 완료 달력·지역별·카테고리별·요일별 통계.
12. **업무 이관** — 요청·수락·기록 연결·알림.
13. **보고서 보관함·다운로드 관리** — 검색·이력·수정본 재다운로드.
14. **웹 관리·건별 보고서 편집** — 사무실에서의 작업.
15. **프로젝트 업무 묶음·통합 보고서** — 지도·카드 편집·원본 보존·확정·버전·HTML/HWPX.
16. **업무 알림·계정 지원** — 실제 활성 조건을 확인해 보충 소개.

선택 전에는 이 목록을 ‘16장 필요’나 ‘전체 발표 몇 장’으로 환산하지 않는다. 하나의 영상·장표에서 여러 항목을 함께 설명할 수 있다.
