# 국내 도로데이터 + Valhalla 사하구 비교

2026-10-26. 로컬 연구용 변환·실행 결과다. 운영 앱·서버의 경로 공급자를 변경하지 않았다.

## 판단

국내 ITS 차량 도로망을 Valhalla에 연결하고 실제 경로를 계산하는 데 성공했다. 그러나 현재 구성으로 카카오 SDK 안내를 대체해서는 안 된다. **다선초등학교의 북쪽 도로 도착 문제가 국내 ITS와 OSM 구성 모두에서 재현됐다.** 경로 탐색의 성공, 도로 규칙 준수, 시설의 올바른 도착점 선택은 서로 다른 검증 대상이다.

국내 보행용 연결망은 이번 조사에서 확보하지 못했다. 국내 차량 도로망에 보행을 임의 허용하지 않았으며, 국내 데이터의 도보 비교를 완료했다고 주장하지 않는다.

## 발할라와 OSM의 관계

Valhalla는 경로 계산 엔진, OSM은 도로·보행로 데이터다. 비교 가능한 구성은 `국내 데이터 + Valhalla`, `OSM + Valhalla`다. OSM 형식으로 국내 자료를 변환한 것은 도로 출처를 OSM으로 바꿨다는 뜻이 아니다.

## 국내 자료와 변환

- ITS 국가교통정보센터의 2026-10-14 표준 노드·링크 공개 파일을 내려받았다. 전국 자료: 링크 1,564,022개, 노드 1,184,340개, 회전정보 44,077개.
- 사하구와 인접 부산 지역을 포함한 경위도 128.87~129.16, 34.98~35.23 범위와 교차하는 링크 29,107개를 추출했다. 전국 전체 그래프가 아니므로 원거리 우회 비교에는 사용하지 않는다.
- 공식 ITRF2000 Central Belt 좌표계를 WGS84로 변환했다. F_NODE/T_NODE를 보존하고 차량 흐름 방향으로 단방향 링크를 만들었다. 평면에서 교차한다고 노드를 합치지 않았다. 원본 링크 끝점과 공식 노드 간 오차는 0m였다.
- 공식 코드표의 ROAD_USE는 0=사용, 1=미사용이다. 미사용 294개와 기타 제한차량 코드가 불명확한 링크 3개를 제외했다. 남은 차량 링크는 28,810개다.
- 제한속도·차로 수·교량·터널을 옮겼다. 도로 관리 등급을 Valhalla 도로 중요도로 옮기는 매핑은 근사다. 제한속도가 실제 평균 주행속도라는 뜻은 아니다.
- 회전금지·좌회전금지·직진금지·우회전금지·버스 전용 회전을 차량 제한으로 변환했다. 허용 유턴과 P턴 기록을 금지로 해석하지 않았다.
- 내부 교차로 연결을 최대 8링크/300m의 단순 경로로 추적해 956개 제한 관계를 생성했다. 이 중 877개는 중간 도로를 포함한다. 시간제 제한 1개는 시간표가 없어 전일 금지로 보수적으로 처리했다.
- **54개 회전 제한은 연결 경로를 찾거나 확정하지 못했다. 사하구 링크로 시작하는 항목도 15개 포함된다.** 따라서 전체 회전 제한을 반영한 완성형 변환이 아니다. 제외된 링크와 관련된 회전 기록 271개도 별도 집계했다.
- Valhalla 3.9.1 네이티브 Windows 실행 파일로 별도 타일을 만들었다. OSM 도로는 국내 그래프에 섞지 않았다. 국가 행정구역 DB는 기존 OSM 기반 DB를 재사용했다. 실시간·과거 교통, 외부 고도, 시간대 DB는 연결하지 않았다.
- 도보는 명시적으로 허용하지 않았다. 차량 차선을 보행로·횡단보도로 간주하는 잘못된 비교를 막기 위한 연구 설정이다.

## 차량 400구간 로컬 실행

사하구 공개 장소 20곳과 고정 출발점의 기존 표본을 사용했다. 출발점→20곳 및 방문지 사이의 방향별 380구간, 합계 400구간이다.

| 항목 | 결과 |
|---|---:|
| 국내 ITS + Valhalla 경로 응답 | 400 / 400 성공 |
| 저장된 카카오 차량 시간 대비 시간 비율 중앙값 | 55.62% |
| 절대 시간 차이 비율 중앙값 | 44.38% |
| 경로 계산 및 별도 검사 시간 중앙값 | 약 2.75ms |
| 입력 좌표와 경로 끝점/시작점 차이 최대 | 345.56m |
| 시작 또는 끝점 차이가 100m를 넘는 구간 | 175 / 400 |

카카오의 과거 교통 반영 관측값과, 교통이 없는 로컬 모델을 비교한 값이다. 실주행 오차나 정확도 지표가 아니다. 공원 중심 좌표가 포함되어 있어 실제 출입구와도 다르다. 거리·시간 숫자가 작다고 더 좋은 경로라고 판단할 수 없다.

경로를 다시 원본 링크 ID로 추적해 단방향·제외 링크와 회전 제한 순서를 검사했다. 381구간은 정확 추적이 성공했고, 19구간은 `edge_walk` 추적이 실패하여 검사하지 못했다. 이 19개는 경로 생성 실패가 아니다. 추적한 구간에서 역방향 및 제외 링크 이용은 검출되지 않았다. 2구간은 금지된 출발 링크→도착 링크 순서가 300m 이내에서 다시 등장했다. 상세히 보면 교차로 내부 링크를 한 바퀴 도는 경로였다. 단순 금지 회전 위반으로 확정할 수 없으며, 교차로 내부 순환을 통한 우회가 현실적으로 가능한지 검증해야 한다. 전체 400구간의 합법성을 검증했다는 뜻이 아니다.

## 카카오 API 5개 구간 새 조회

차량 `priority=TIME`으로 5회 새 조회했다. 최단거리로 목표를 바꾸지 않았다. 아래 국내/OSM은 동일 입력 좌표에 대한 Valhalla auto 기본 모델이다. 엔진이 도로에 연결한 지점은 다를 수 있다. OSM은 앞서 만든 한국 전체 그래프 결과를 재사용했다. 선택한 표본과 특이 구간이므로 사하구 전체를 대표하는 무작위 표본이 아니다.

| 출발 → 도착 | 카카오 거리 / 시간 | 국내 ITS + Valhalla | OSM + Valhalla |
|---|---:|---:|---:|
| 다대포해수욕장역 인근 → 열림공원 | 1,573m / 237초 | 1,466m / 106.3초 | 1,586m / 114.8초 |
| 다대포해수욕장역 인근 → 신평레포츠공원 | 6,572m / 500초 | 6,667m / 386.7초 | 약 6,053m / 약 355초 |
| 부민산공원 → 동아대 뉴턴의사과나무공원 | 6,904m / 771초 | 6,127m / 455.3초 | 약 5,433m / 약 409초 |
| 동아대 뉴턴의사과나무공원 → 부민산공원 | 5,527m / 731초 | 5,185m / 396.5초 | 약 5,607m / 약 401초 |
| 장림유수지 → 신평레포츠공원 | 3,146m / 345초 | 1,791m / 161.9초 | 약 1,506m / 약 132초 |

국내 자료가 카카오와 가까운 구간도, OSM이 가까운 구간도 있다. 장림유수지 구간처럼 경로 자체가 크게 갈리는 사례가 남아 있다. 신평레포츠공원 경로 모양이 비슷해도 시간 모델은 다르다.

## 다선초 재현 — 도착점 문제

사용자 지적으로 과거 Android 통합 테스트에 고정된 출발점·학교 중심 좌표를 사용해 두 로컬 엔진을 실행했다. 새로운 카카오 SDK 실기기 호출은 하지 않았고, SDK 비교 기준은 2026-10-14 기록이다. 실시간 교통 조건이 같지 않으므로 시간의 우열을 비교하지 않는다.

| 구성 | 거리 / 시간 | 경로 끝점 | 위치 |
|---|---:|---|---|
| 과거 카카오 SDK 기본 | 387m / 139초 | 35.0630442, 128.9849105 | 학교 남쪽 도로 |
| 과거 카카오 SDK 주변 도로 허용 MP | 940m / 240초 | 35.0640839, 128.9856466 | 학교 북쪽 도로 |
| 이번 국내 ITS + Valhalla auto | 1,666m / 173.0초 | 35.0640430, 128.9856440 | 학교 북쪽 도로 |
| 이번 OSM + Valhalla auto | 832m / 84.1초 | 35.0641000, 128.9856400 | 학교 북쪽 도로 |

**국내 도로데이터로 바꿔도 학교 대표 좌표를 올바른 출입구로 바꾸는 기능이 자동으로 생기지 않는다.** 현재 로컬 두 구성 모두 사용자가 지적한 북쪽 도착 문제를 재현했다. 해당 학교 정문/후문의 현재 차량 진입 가능성은 현장에서 확인한 것이 아니다.

현재 앱은 사용자 결정에 따라 출입구 자동 보정을 철회하고 카카오 SDK 안내를 사용한다. 이번 연구로 자동 보정을 되살리거나 운영 경로를 변경하지 않았다. 후속 비교에서는 장소 좌표와 안내 도착점을 구분하고, 출입구의 시설 소속·교통수단별 접근 가능성·실제 경로 종점을 검증해야 한다. 지도에 직접 찍은 노상 방문지를 주변 건물 입구로 임의 변경해서는 안 된다. 미리보기와 실제 안내가 다른 도착점을 사용하지 않는지도 확인해야 한다.

## 국내 도보 비교가 완료되지 않은 이유

- ITS 표준 노드·링크는 이번에 확보한 차량 도로망이다. 차량 차선을 양방향으로 열어 도보 결과를 만드는 것은 보행로·횡단보도·계단·출입구·담장 연결을 검증한 것이 아니다.
- 주소기반산업지원서비스의 공개 카탈로그에서 도로 도형·건물 출입구·도로명주소 전자지도·내부도로·입체도로 자료를 확인했다. 전자지도는 신청 및 관할기관 승인 후 제공되는 자료다. 이 조사에서 신청서를 제출하거나 승인 자료를 확보하지 않았다. 자료를 받더라도 라우팅 가능한 보행 연결망과 접근 규칙을 갖췄는지 별도 확인해야 한다.
- KTDB는 교통분석용 네트워크와 신청 절차를 확인했다. 이번 사하구 전역의 완전한 보행 연결망 파일을 확보한 것은 아니다.
- 부산연구원의 공개 검색 결과에는 2022년 부산 연속수치지도 도로중심선 자료가 있으나 상세 페이지가 HTTP 400으로 실패했다. 그 파일을 내려받거나 경로망으로 검증하지 못했다.
- 서울의 보행자 도로 네트워크 자료는 존재하나 사하구 데이터로 사용할 수 없다. 국내 보행 데이터가 전혀 없다는 결론은 아니다.

참고로 앞선 **OSM + Valhalla** 도보 400구간은 모두 계산됐지만, 샛별어린이공원→희망어린이공원에서 카카오 3,461m/5,518초와 OSM 1,146m/810초로 크게 달랐다. 카카오 SHORTEST 진단도 3,448m/5,512초여서 단순 옵션 차이만으로 설명되지 않았다. 어느 경로가 실제 통행 가능한지 현장 검증하지 않았다. 이 수치를 국내 보행 데이터의 결과로 제시하지 않는다.

## 재현과 원시 결과

- `tools/research-domestic-road-data.py`: 공개 자료 카탈로그 확인.
- `tools/download-domestic-node-link.py`, `tools/inspect-domestic-node-link.py`: 공식 자료 다운로드, 허용한 파일만 추출, 범위 및 필드 검사.
- `tools/build-domestic-valhalla.py`: ITS 차량 링크/회전 규칙을 별도 PBF와 Valhalla 타일로 변환. 실패한 변환 출력은 완료 파일로 취급하지 않는다.
- `tools/compare-domestic-valhalla.py`: 400구간과 별도 규칙 검사, 카카오 TIME 5구간 새 조회. 원시 응답 요약·경로를 캐시하고 재실행 시 외부 호출을 반복하지 않는다.
- `tools/render-domestic-route-comparison.py`: 경로 선 비교 그림. 배경지도가 없으며 현장 검증 결과가 아니다.
- `tmp/domestic-road-comparison/`: `conversion.json`, `unresolved-turns.json`, `comparison.json`, `fresh-examples.json`, `dasun-replay.json`, `build.log`, `route-comparison.png`.
- 다선초 기준: `frontend/modules/kakao-navigation/android/src/integrationTest/java/com/pang3/probe/NavigationProbeTest.kt` 및 `docs/archive/navigation/NAVIGATION_FINDINGS_2026-10-14.md`.
