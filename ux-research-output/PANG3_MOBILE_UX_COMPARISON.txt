1. 결론과 사용자 고정 요구사항

두 보고서의 공통 결론은 화면 스타일보다 현장 기록의 연속성, 사진 보존, 저장 결과의 이해, 업무 맥락 유지가 먼저라는 것이다. 공통 발견을 우선 개선안으로 통합하고, 서로 다른 발견은 코드에서 추가 확인했다. 보고서끼리 일치한다는 사실만으로 사용자 불편의 빈도나 효과가 입증되지는 않는다.

사용자 최신 요구: “작업 전/작업 중/작업후 이거는 못바꿔 그사람들이 이렇게해달라고했기때문에”.
따라서 표시 명칭 ‘작업 전 / 작업 중 / 작업 후’를 유지한다. 상태 선택과 사진 단계에 모두 적용한다. pending / working / complete의 기존 대응과 완료된 기록의 수정 제한도 임의 변경하지 않는다. Claude의 ‘작업 후 → 완료’ 제안은 채택하지 않는다. 안내 문구와 저장 전 설명은 보완할 수 있지만 단계명 교체나 새로운 업무 상태 추가로 해결하지 않는다.

이번 작업은 비교·프롬프트 작성이다. 앱 코드 수정, 운영 데이터 변경, 업무 처리, 배포를 수행하지 않았다. 원본 두 보고서를 보존한다. 병합 프롬프트도 조사·개선안 작성용이며 구현 권한을 자동 부여하지 않는다.

2. 공통 발견과 추가 발견의 통합

M01 사진의 유지·교체·삭제와 단계 식별 — 최우선
Codex F02 / Claude F04.
FieldActionScreen은 기존 사진을 배열 위치로 슬롯에 넣고 새 로컬 URI만 업로드한다. TaskProgressService는 새 기록에 이번 요청의 사진을 연결하고 최신 기록을 읽는다. 이 조합은 기존 사진이 최신 기록에서 누락되거나 단계가 잘못 배치되는 조건을 만든다. 원본 파일의 물리적 삭제가 확인된 것은 아니다.
통합안: PHOTO_TYPES를 명시적으로 보존하고 기존 사진 유지, 새 사진 교체, 사용자의 의도적 삭제를 구분하는 저장 계약을 설계한다. 프런트만 고쳐도 충분하다고 단정하지 않는다. 과거 이력과 권한·완료 제한을 유지한다.
근거: frontend/screens/FieldActionScreen.js의 기존 사진 로딩과 업로드 구성, backend의 TaskProgressService 최신 기록·사진 저장 처리.

M02 모든 이탈 경로에서 작성 내용 보호 — 최우선

통합안: 변경 여부와 저장 중 여부를 하나의 판단으로 관리하고 실제 활성 이탈 경로를 모두 연결한다. 돌아와도 작업 대상·그룹·사진 단계가 같아야 한다. 초안 저장은 별도 설계 항목이다.

M03 촬영 후 편집 취소와 원본 사용 — 최우선 보완
Claude F03; Codex의 기록 보존 문제를 구체화.
새 촬영·갤러리 선택은 편집기로 넘어가며 편집 완료 후 슬롯에 커밋된다. 편집기를 닫으면 새 사진은 슬롯에 들어가지 않는다. 따라서 새 사진에는 ‘원본 사용’과 명시적 버리기를 구분할 필요가 있다. 기존 사진 편집 취소는 기존 슬롯을 유지해야 한다. 모든 취소를 원본으로 덮어쓰는 방식은 채택하지 않는다.

M04 저장 의미·완료 제한·처리 대기 설명 — 최우선
Codex F03 / Claude F02·F05·F13.
현재 저장은 기록·상태와 보고서 생성 처리에 연결된다. 작업 후 저장 뒤 수정 제한을 안내해야 한다. 실재하지 않는 제출 API를 가정해 ‘완료로 제출’이라고 바꾸지 않는다.
통합안: 단계명과 기존 저장 행동을 유지하며 현재 상태, 작업 후 저장 시 수정 제한, 처리 중 중복 입력 방지, 실패 후 입력 유지, 성공 결과를 설명한다. 단일 multipart 요청이면 사진별 업로드 완료 숫자를 만들어 보여주지 않는다. 서버 확인 없이 저장 성공·생성 완료라고 선언하지 않는다. 백그라운드 생성은 후속 구조 변경안이다.

M05 도착 → 작업 시작 → 현장 기록 연결 — 다음 우선순위

통합안: 서버 성공 확인 후 작업 시작 결과와 현장 기록 진입을 연결한다. 이동 중 폼 자동 실행이나 실패했는데 working 표시하는 행동은 피한다. 명시적 ‘현장 기록’ 행동과 자동 진입을 비교하되 전자를 기본 제안으로 삼는다.
한계: 네이티브 SDK 종료 이벤트와 도착 표시의 실제 순서에 따른 증상은 실기기 검증 전 가설이다.
근거: KakaoMapWebView.js의 arrival action, MapScreen.js의 onLocationsChange/onEnded, KakaoNavigationView.kt 종료 이벤트.
