1. 요약
--------------------------------------------------

현재 모바일 앱의 핵심 흐름(코드 기준)
  로그인 → (곧바로) 지도 → 방문지 칩/마커 탭으로 경로 미리보기 → ▶ 안내 시작
  → (Android 차량: 카카오내비 SDK 화면 / 그 외: 앱 지도 위 경로) → 100m 이내 도착 시트 "작업 시작"
  → 방문지 다시 탭 또는 안내 카드 이름 탭 → "보고서 양식 작성"(사진 전/중/후·메모·상태)
  → "보고서 저장" → 지도로 복귀 → 다음 방문지를 다시 골라 안내 시작

UI 자체보다 갑갑함을 만드는 원인은 다음 네 가지로 모인다 [C]:
  (1) 현장 도착과 기록 사이의 연결이 끊겨 있다. 도착 시트의 "작업 시작"은 상태만 바꾸고 기록 화면을 열지 않는다.
      기록 화면으로 가는 입구는 "같은 마커를 한 번 더 탭"하거나 "안내 카드의 이름을 탭"하는 숨은 동작이다. (F01)
  (2) "완료"가 무엇인지 화면마다 말이 다르고, 되돌릴 수 없다. 기록 화면의 상태 버튼은 사진 단계와 같은
      "작업 전/중/후"이며, "작업 후"를 고른 채 "보고서 저장"을 누르면 서버가 그 방문지를 영구 잠근다. (F02)
  (3) 작성 중인 현장 기록이 쉽게 사라지거나 빠진다. 임시저장이 없고, 사진 촬영 직후 편집기에서 "취소"를 누르면
      방금 찍은 사진이 버려진다. 중간 저장 후 다시 저장하면 앞서 올린 사진이 최신 기록에서 빠지는 구현 오류가 있다. (F03, F04)
  (4) 한 곳을 끝낸 뒤 다음 곳으로 이어지지 않는다. 저장하면 안내가 종료되고, 다음 목적지를 다시 고르고 경로를
      다시 불러와야 한다. (F06)

가장 먼저 풀 후보 (자세한 근거는 7·9장)
  1순위 F04 중간 저장 시 이전 사진 누락 — 구현 오류, 데이터 손실, 수정 범위 작음~중간
  2순위 F01 도착 → 기록 진입 연결 — 현재 기능 재배치, 작음
  3순위 F02 완료 용어·확정 단계 정리 — 문구와 확인 단계 추가, 작음
  4순위 F03 작성 중 기록 보호(사진 편집 취소·임시저장·Android 카메라 복귀) — 작음~중간
  5순위 F06 완료 후 "다음 방문지" 제안 — 중간
  모두 "새 기능 추가"보다 "있는 흐름을 이어 붙이고 용어를 정리"하는 안이다.

가장 큰 불확실성
  - 실제 사용자가 하루에 몇 곳을 어떤 순서로 도는지, 한 방문지에서 중간 저장을 하는지 (사용 빈도 미확인)
  - Android 카카오내비 SDK 안내가 목적지 도착으로 끝날 때 앱의 도착 시트가 뜨는지 (이벤트 순서, 현장 확인 필요)
  - "완료" 이후 수정 불가가 업무 정책인지 (책임 추적 목적이라면 유지해야 함)

3. 참고 파일에서 가져온 분석 방법과 제외한 사항
--------------------------------------------------

참고 파일: "심층분석 과정.txt" (다른 팀원의 Godot 게임 프로젝트 사례)

가져온 것 (방법만)
  사용자 의도 해석 → 모호성 분리 → 현재 구현(코드)과 외부 자료 조사 → 대안 비교 → 근거 있는 추천 → 미정 질문 정리
  - 좋은 점: 사용자의 초안을 "확정 요구"가 아니라 "검증할 가설"로 다루고, 사실/반응/추론/가설을 나눈다.
  - 이번에 맞게 바꾼 점: 게임의 "재미 루프" 대신 "외근 업무 루프(이동→도착→기록→완료→다음)"를 분석 단위로 삼았다.
    유사 게임 리뷰 대신 현장 업무 앱의 공식 문서·리뷰를 근거로 삼았다.

제외한 것
  - 게임 규칙, 에셋 탐색, 예산, 모델명/추론 설정 지시, AGENTS/CLAUDE/GOAL/PLAN 등 운영 문서 재작성 지시
  - "두 모델 결과를 비교·통합하는 문서 체계" 구성 — 이번 보고서는 독립 분석만 수행

4.1 앱의 목적과 사용자 (근거)
  [A] README: "사하구청 지도 기반 외근 도우미" — 외근 경로 관리, 업무 기록, 보고서 자동화.
  [A] 구현상 역할 구분:
      - 모든 사용자는 "개인 업무공간"(personalWorkspace) 하나와 0개 이상의 "그룹"을 가진다 (App.js:50-55, 233-257).
      - 그룹에는 role 필드가 있고 'LEADER' 분기가 있다(App.js:171-177). 그러나 이 값을 쓰는 지도(publicDataAssignment)는
        활성 화면에서 들어갈 방법이 없다(4.2 참고).
      - 방문지 기록 저장은 "현재 담당자만" 가능 (TaskProgressService.java:149-157).
  [C] 따라서 모바일의 실질적 사용자는 "외근 담당자(개인 또는 그룹 구성원)" 한 종류이고, 그룹 기능은
      초대·팀원 관리·업무 이관·업무 현황 보기 중심이다. "배정 담당자"의 모바일 배정 흐름은 활성 경로에 없다.

4.3 주요 상태 연결 (코드)
  - 방문지 상태: pending(작업 전) → working(작업 중) → complete(완료). 서버 Task 상태가 기준.
      working 전환: 도착 시트 "작업 시작"(KakaoMapWebView.js:3994-4014) 또는 기록 저장 시 선택한 상태
      complete 전환: 기록 화면에서 "작업 후" 선택 후 저장 (FieldActionScreen.js:1638-1645, 1137-1140)
      complete 이후 서버는 기록 수정을 거부 (TaskProgressService.java:150-151)
  - 오늘 지도에 올라갈 업무: splitWorkPlan이 "지도/미처리"로 나눈다. 오늘 예정 업무는 자동 추가,
    수락한 이관 업무는 사용자가 "미처리 업무"에서 직접 골라야 지도에 올라감 (App.js:339-347, workPlan.js).
  - 경로 세션: 단일 목적지 안내. 업무공간·날짜별로 AsyncStorage에 저장되어 앱 재실행 후에도 복원 (App.js:484-498, routeSession.js).
  - 현장 기록(사진·메모): 화면 메모리에만 있다. 저장 버튼을 누를 때 서버로 한 번에 업로드.

4.4 사용자 여정 지도 (현재, 코드상 추정)

 J1 하루 시작
   앱 실행 → 로그인(매번; 세션 저장 없음, App.js:80) → 지도(GPS 확인 전까지 지도 미표시)
   → 상단 칩 줄에서 오늘 방문지 확인, "미처리 업무 N건 보기"로 오늘 지도에 없는 업무 확인

 J2 이동
   방문지 칩/마커 탭 → 경로 미리보기 카드(이름·거리·시간, 차/도보 아이콘, ▶) → ▶ 안내 시작
   → Android+차: 카카오내비 SDK 전체 화면 / 그 외: 앱 지도에 경로, 60m 이탈 시 재탐색

 J3 도착·현장 기록
   100m 이내 → "작업 지점 근처에 도착했습니다 / 나중에 · 작업 시작" 시트
   → "작업 시작"은 상태만 working으로 바꾸고 시트를 닫음 → 사용자가 다시 마커나 카드 이름을 탭 → 기록 화면
   → 사진(전/중/후 각 슬롯: "사진 촬영/앨범 선택" 선택창 → 카메라 → 사진 편집기 "저장") + 메모(음성 입력 가능)
   → 맨 아래 "상태"에서 작업 전/중/후 선택 → "보고서 저장"(AI 정리 생성까지 대기) → 이전 화면으로 복귀

 J4 다음 방문지
   저장으로 완료된 목적지는 안내가 자동 종료(MapScreen.js:1179-1188) → 다시 J2 반복

 J5 보고서 확인·제출
   하단 "보고서" 탭 → 오늘 지도 방문지 목록(작업 전 항목은 선택 불가) → 여러 개 선택 → 보고서 미리보기
   → "보고서 파일 열기" → HWPX 파일을 브라우저/외부 앱으로 엶 (선택한 것 중 첫 파일만, F10)

 J6 그룹
   하단 "그룹" → 그룹 목록 → (다른 그룹이면 첫 탭은 "선택"만, 두 번째 탭에서 진입) → 대시보드/업무 이관/설정
   이관: 받는 팀원 선택 → 방문지(행정동 단위 묶음 선택 가능) 선택 → 요청 / 받은 사람 수락·거절
   초대: 설정 → 팀원 관리에서 아이디로 초대 / 받은 초대 수락

 J7 알림
   업무 배정·담당자 변경·우선순위 변경 푸시 탭 → 이력 초기화 후 'main' = 통계 대시보드로 이동 (App.js:773-785, 945-951)

공통 원인 [C]
  C1 "상태 변경"과 "다음 화면 이동"이 분리되어 있다 → F01, F06, F08
     기능은 다 있는데(도착 감지, 추천 순서, 미처리 목록) 끝난 뒤 사용자를 다음 지점에 놓아주지 않는다.
  C2 한 단어가 여러 뜻, 한 버튼이 여러 효과 → F02, F10, F13
     "작업 후", "보고서 저장", "보고서 만들기", "홈으로 돌아가기"가 실제 효과와 다르다.
  C3 현장 입력의 내구성 부족 → F03, F04, F05
     입력은 메모리에만, 저장은 한 번에 크게, 서버는 덮어쓰는 구조.
  C4 맥락(업무공간·이력)이 보이지 않음 → F07, F09, F11

개선 방향 (현재 UI 유지 우선)
  - 새 화면을 만들지 않고, 기존 시트·카드·버튼의 "다음 행동"을 명확히 한다.
  - 데이터 손실(F04, F03)은 시각 변화가 거의 없어도 최우선.
  - 책임 추적 장치(완료 후 잠금, 이관 수락, 미저장 확인)는 유지하고 "설명과 확인"을 더한다.

주요 판단 (D번호)

D01 도착 후 기록 진입 방식 (J3, F01)
  선택지: (a) 현행 유지 (b) 도착 시트에 "작업 시작하고 기록 열기" (c) 도착 즉시 기록 화면 자동 이동
  추천: (b) / 이유: 한 번의 의도된 탭으로 상태 변경+진입, "나중에" 유지로 통제권 보존
  근거: [A] 3978-4056, [B] Field Maps Start/Finish, Dynamics In Progress=도착
  반대 근거: 도착 후 바로 기록하지 않고 주민 응대부터 하는 경우 (b)도 불필요할 수 있음 → "나중에"로 해결
  확신도: 중간 / 바뀌는 조건: 현장에서 도착 시트 자체가 방해라는 반응이 많으면 시트 대신 하단 고정 바(F01 대안)
  사용자 답변: Q5 있으면 좋음

D02 완료 확정 방식 (J3, F02)
  선택지: (a) 상태 버튼+저장 유지, 용어만 통일 (b) "기록 저장"/"완료로 제출" 버튼 분리+확인창 (c) 완료 잠금 제거
  추천: (a)+(b)의 최소형 — 용어 통일, 저장 버튼 문구를 상태에 따라 변경, 완료 시 확인창
  이유: 잠금 정책은 유지하면서 실수만 막음. (c)는 책임 추적 정책을 바꾸므로 기각(사용자 결정 전)
  확신도: 중간~높음 / 사용자 답변: Q3·Q4

D03 작성 중 기록 보호 위치 (F03)
  선택지: (a) 기기 임시저장(AsyncStorage) (b) 서버 초안 저장 (c) 현행
  추천: (a) / 이유: 서버 변경 없이 프로세스 종료·실수 이탈 모두 대응, 오프라인에도 동작
  반대 근거: 다른 기기에서 이어 쓰기 불가 → 현장 1인 1기기라면 문제 없음(Q6과 함께 확인)
  확신도: 중간

D04 사진 누적 방식 (F04)
  선택지: (a) 서버가 이전 기록의 사진 이어받기 (b) 앱이 유지할 사진 목록 전송 (c) 방문지당 1건 구조로 재설계
  추천: (a) 또는 (b) — 백엔드 담당자가 데이터 호환을 보고 선택. (c)는 범위가 커서 이번 목적에 과함
  확신도: 높음(문제 존재), 해결 방식은 팀 판단

D05 AI 정리 생성 시점 (F05)
  선택지: (a) 현행 동기 + 진행 문구 개선 (b) 저장과 분리(비동기)
  추천: 먼저 (a)로 실패 문구·재시도부터, 대기 시간을 측정한 뒤 (b) 판단 / 바뀌는 조건: 실측 대기 10초 이상이 잦으면 (b)
  확신도: 중간 / 사용자 답변: Q7

D06 완료 후 다음 방문지 (F06)
  선택지: (a) 현행 (b) 다음 추천 카드 표시(수동 시작) (c) 자동 안내 시작
  추천: (b) / 이유: 탭과 탐색을 줄이되 운전 중 의도치 않은 안내 시작 방지
  근거: [B] Spoke 완료 시 다음 정류장 자동 전환 / 반대 근거: 현장에서 순서를 자주 바꾸면 카드가 무시될 뿐 해는 적음
  확신도: 중간 / 사용자 답변: Q1

D07 업무공간 표시·전환 (F07)
  선택지: (a) 지도 배지 + 한 번 탭 진입 (b) 모든 업무공간 통합 지도 (c) 현행
  추천: (a) / (b)는 경로 세션·권한 구조 변경이 커서 기각(지금 단계)
  사용자 답변: Q8

D08 새 업무 유입 (F08)
  선택지: (a) 알림 → 지도+미처리 시트, 수락 직후 "지금 추가" 선택 (b) 이관도 자동 추가 (c) 현행
  추천: (a) / 이유: "받은 사람이 언제 할지 고른다"는 현재 의도를 유지하면서 경로만 단축. (b)는 정책 결정 필요(Q9)

D09 뒤로가기 모델 (F09)
  선택지: (a) 탭 전환 시 이력 초기화(탭 내부 스택만) (b) 현행 전역 이력
  추천: (a) / 이유: 일반적인 하단 탭 앱의 기대와 일치(익숙한 패턴, UI_UX_GUIDELINES 4장)
  반대 근거: 지도↔보고서를 오가며 뒤로가기로 돌아오는 사용 습관이 있다면 혼란 → S5로 확인

D10 신규 기능 vs 흐름 다듬기
  추천: 이번 목적("갑갑함 해소")에는 흐름 다듬기. 엑셀 일괄 등록·사진으로 등록·통합 지도·하루 묶음 보고서·오프라인 모드는 기각 또는 보류.
  이유: 현재 막힘은 기능 부족보다 기존 기능 사이의 연결과 용어에서 생긴다는 것이 코드상 확인됨.

9. 우선순위·의존성·점진적 실행 순서
--------------------------------------------------
(사용 빈도는 모두 미확인. 아래 순위는 "하루 3곳 이상 방문하고, 한 곳에서 사진 2장 이상을 남긴다"는 가정을 둔 것이다.)

층 1 — 작은 범위로 먼저 검증할 개선
  1. F04 사진 누락·칸 뒤바뀜 수정
     수정 후보: TaskProgressService 저장/조회, FieldActionScreen 저장·로드 / 선행 조건: 기존 데이터 호환 방식 결정(D04)
     규모: 작음~중간(백엔드 1개 서비스 + 앱 1화면) / 실패 위험: 기존 기록의 사진 단계 정보가 없어 추정 필요
     완료 기준: 같은 방문지에 2회 저장(전→후) 후 다시 열면 전·후 사진이 각 칸에 있고, HWPX에 둘 다 포함
  2. F01 도착 시트 "작업 시작하고 기록 열기" + 안내 카드 "기록" 버튼 + PATCH 실패 처리
     수정 후보: KakaoMapWebView 도착 모달, MapScreen 카드 / 규모: 작음 / 실패 위험: 낮음
     완료 기준: 도착 시트에서 1탭으로 기록 화면, 상태 PATCH 실패 시 상태가 바뀌지 않고 안내 문구 표시
  3. F02 용어 통일·저장 버튼 문구·완료 확인창
     수정 후보: FieldActionScreen, ReportListScreen 라벨 / 규모: 작음 / 선행: Q3(잠금 정책) 답 없으면 "잠금 유지" 가정으로 진행 가능
     완료 기준: 앱 전체에서 complete가 "완료"로 표시, 완료 제출 전 수정 불가 안내가 반드시 나옴
  4. F03 최소형: 편집기 "취소"가 사진을 버리지 않게, getPendingResultAsync 적용, 방문지별 임시저장
     규모: 작음~중간 / 실패 위험: 임시본과 서버본 충돌 → "서버본이 더 최신이면 임시본 폐기" 규칙
     완료 기준: "활동 보관 안함" 상태에서 촬영해도 사진 유지, 앱 강제 종료 후 재진입 시 메모 복원
  5. F13 오류 문구, F12 중 "준비 중" 메뉴 숨김·버튼 크기 — 작음, 언제든 병행

층 2 — 관련 흐름을 함께 고쳐야 효과가 나는 개선
  6. F06 완료 후 다음 방문지 카드 (F02의 "완료로 제출" 이후 흐름에 연결되므로 F02 다음)
  7. F08 알림 → 지도·미처리 시트, 이관 수락 직후 "오늘 지도에 추가" (F07 배지와 같이 하면 맥락이 명확)
  8. F07 업무공간 배지·한 번 탭 진입·전환 확인
  9. F09 탭 전환 이력 정리, iOS 스와이프의 기록 화면 보호 (화면 이동 전반 회귀 점검 필요 → 중간)
  10. F05 저장 진행 문구·재시도, AI 오류 문구 정리 (비동기 분리는 층 3)
  11. F10 보고서 미리보기 방문지별 파일 열기, 번호 일치

층 3 — 사용자 결정·현장 검증 후 판단
  - KNSDK 안내 종료 시 도착 처리(F01 가설) — Android 실기기 차량 시험 후
  - 로그인 유지(F03 대안) — 보안·기기 정책(Q6)
  - AI 정리 비동기 분리(F05 대안) — 실측 대기 시간 후
  - 하루 묶음 보고서(F10 대안), 이관 자동 추가(F08 대안), 통합 지도(F07 대안), GPS 정확도 반영(F11 대안)
  - 완료 후 수정 허용/후속 방문 상태(F02, Dynamics 사례) — 업무 정책

최우선 3~5개와 이유
  F04(데이터 손실) → F01(매 방문 반복되는 막힘, 작은 수정) → F02(되돌릴 수 없는 실수 예방) → F03(현장 입력 보호) → F06(반복 비용)
  F04와 F03은 "새 기능"이 아니라 "이미 입력한 것을 잃지 않게" 하는 것이고, F01·F02·F06은 기존 기능을 연결·재명명하는 것이다.

10. 추천안의 과업별 검증 계획
--------------------------------------------------
(실제 테스트는 하지 않았다. 아래 기준선은 측정값이 아니라 "코드상 추정"이며 목표는 제안값이다.
 측정 후보: 과업 성공 여부, 기록 화면까지의 탭 수, 화면 왕복·재입력 횟수, 다음 행동을 찾는 데 머뭇거린 지점, 중단 후 복구 여부.
 진행: 실제 외근 담당자 3~5명, 테스트 계정·테스트 방문지, 관찰자가 화면 녹화 또는 메모. 별도 분석 도구 불필요.)

S1 연속 방문 기본 과업 (F01, F02, F05, F06)
  시작 조건: 오늘 지도에 테스트 방문지 3곳, 위치 권한 허용, 도보 모드(시트가 뜨는 경로)
  과업: 1번 방문지로 안내 시작 → 도착 → 작업 전·후 사진 각 1장, 메모 1줄 → 완료 처리 → 2번 방문지 안내 시작
  관찰할 막힘: 도착 후 기록 화면을 찾는 시간, "작업 후" 버튼과 사진 단계 혼동, 저장 대기 중 행동, 다음 방문지 선택 과정
  완료 조건: 1번 완료, 2번 안내 시작
  예외: 도착 시트에서 "나중에" 선택 후 기록 진입 / 저장 중 네트워크 끊김(비행기 모드)
  기준선(추정): 도착 시트→기록 화면 2탭(숨은 탭 포함) / 목표: 1탭, 다음 방문지 안내 시작까지 2탭 이내

S2 기록 중단·복귀 (F03)
  시작 조건: Android, 개발자 옵션 "활동 보관 안함" 켬
  과업: 메모 작성 → 사진 촬영 → 편집기에서 바로 "취소" → 다른 칸 사진 촬영 → 앱을 최근 앱에서 종료 → 재실행 후 같은 방문지 기록 열기
  관찰: 사진 유지 여부, 메모 복원 여부, 재로그인 부담
  완료 조건: 처음 입력한 메모와 사진이 모두 남아 있음 / 예외: 촬영 권한 거부

S3 중간 저장 후 추가 저장 (F04)
  과업: 작업 전 사진만 넣고 "작업 중"으로 저장 → 나갔다가 다시 열기 → 작업 후 사진 추가 후 완료 → 보고서 미리보기·파일 확인
  관찰: 다시 열었을 때 사진이 어느 칸에 있는지, 최종 파일에 두 사진 포함 여부
  완료 조건: 전·후 사진이 각 칸과 보고서에 모두 존재

S4 새 업무 받기 (F07, F08)
  시작 조건: 개인+그룹 소속 사용자, 다른 팀원이 이관 요청 / 배정 알림 발송(테스트 환경)
  과업: 알림을 눌러 받은 업무를 오늘 지도에 올리고 안내 시작 / 이관 요청을 수락하고 오늘 지도에 올리기
  관찰: 알림 후 도착 화면, 업무공간 확인 방법, 미처리 목록을 찾는 경로
  완료 조건: 받은 업무가 지도에 표시되고 안내 시작

S5 뒤로가기 예측 (F09)
  과업: 지도 → 보고서 탭 → 방문지 기록 → 뒤로 → 그룹 탭 → 그룹 진입 → 뒤로가기만으로 지도까지 돌아오기 (Android 버튼, iOS 스와이프 각각)
  관찰: 예상과 다른 화면이 나온 횟수, 통계 대시보드 노출 여부, 기록 화면 스와이프 시 미저장 확인 여부
  완료 조건: 참가자가 예상한 순서로 이동

추가 확인(현장 1회): Android 차량 모드로 실제 목적지 도착 — 내비 종료 후 도착 시트가 뜨는지, 지도에 무엇이 남는지 (F01 가설)

   필요한 이유: 다음 방문지 카드(F06)의 가치와 자동 시작 여부 / 연결: F06, D06
   답변별 변화: 순서대로 → 자동 제안 강화 / 자주 변경 → 카드는 제안만, 목록 접근 강화
   임시 가정: 대체로 추천 순서를 따르되 가끔 변경 / 미답변 시 보류: 자동 안내 시작(층 3)

★Q2 [핵심 과업] 한 방문지에서 도착 직후 "작업 전" 사진을 먼저 저장하고, 작업 뒤 다시 저장하는 방식으로 쓰나요?
   필요한 이유: F04의 실제 발생 빈도 / 연결: F04, F03
   답변별 변화: 그렇다 → F04 즉시 최우선 / 아니다(한 번에 저장) → F04 여전히 수정하되 F03 임시저장이 더 중요
   임시 가정: 중간 저장을 일부 사용 / 미답변 시 보류: 없음(F04는 데이터 손실이라 진행 권장)

★Q3 [업무 정책] 완료 처리 후 기록 수정 불가는 의도된 정책인가요? 잘못 완료했을 때 지금은 어떻게 처리하나요?
   연결: F02, D02 / 답변별 변화: 정책 유지 → 확인창 필수 / 수정 허용 필요 → "완료 취소" 권한·이력 설계 필요
   임시 가정: 책임 추적을 위한 정책 → 유지 / 미답변 시 보류: 완료 취소 기능

★Q4 [업무 정책] "추가 방문 필요(미완료로 종료)" 같은 상태가 실제 업무에 있나요? 또는 "작업 전"으로 되돌릴 일이 있나요?
   연결: F02 (Dynamics의 Partially Completed 사례) / 임시 가정: 없음 → 3단계 유지 / 미답변 시 보류: 상태 추가

★Q5 [현장 환경] 도착하면 바로 사진·기록부터 하나요, 아니면 응대·확인 후 한참 뒤에 기록하나요? 차량/도보 비율은?
   연결: F01, D01 / 답변별 변화: 바로 기록 → 도착 시트 1탭 진입 / 나중 기록 → 하단 고정 바(대안)
   임시 가정: 대체로 바로 기록, 차량 이동 많음

Q6 [보안·기기 정책] 업무폰이 개인 전용인가요, 공용인가요? 앱 재실행 시 매번 로그인하는 것이 요구사항인가요?
   연결: F03, D03 / 임시 가정: 1인 1기기, 로그인 유지는 미결 / 미답변 시 보류: 자동 로그인

Q7 [핵심 과업] AI 정리 문장과 보고서 파일이 현장에서 바로 필요한가요, 사무실 복귀 후 확인해도 되나요?
   연결: F05, D05 / 답변별 변화: 나중이어도 됨 → 비동기 분리 추천 / 바로 필요 → 동기 유지+진행 표시

Q8 [실제 사용자] 한 사람이 같은 날 개인 업무와 그룹 업무(또는 여러 그룹)를 함께 처리하나요?
   연결: F07, D07 / 임시 가정: 일부 사용자만 / 미답변 시 보류: 통합 지도

Q9 [업무 정책] 이관받은 업무는 받은 사람이 날짜를 정해야 하나요, 오늘 바로 지도에 올라가도 되나요?
   연결: F08, D08 / 임시 가정: 현재 의도(받은 사람이 선택) 유지

Q10 [업무 정책] 보고서 제출 단위는 방문지 1건마다인가요, 하루 묶음인가요? 누구에게 어떻게 제출하나요(파일 공유/웹 확인)?
   연결: F10 / 임시 가정: 방문지별 HWPX / 미답변 시 보류: 묶음 보고서

Q11 [현장 환경] 실내·지하·고층 주변 등 GPS가 불안정한 현장이 자주 있나요? 도착 판정이 틀린 경험이 있나요?
   연결: F11 / 미답변 시 보류: 정확도 반영

Q12 [우선순위] "근무지 지정", "공공시설물 등록", 지도에서 직접 선택 중 실제로 자주 쓰는 방문지 추가 방법은?
   연결: F12 / 임시 가정: 주소 검색이 주 사용

Q13 [역할] 그룹 리더가 모바일에서 직접 팀원에게 업무를 배정할 필요가 있나요? (현재 배정 화면은 연결되어 있지 않음)
   연결: T1 / 임시 가정: 배정은 모바일 범위 밖 / 미답변 시 보류: 배정 화면 연결 여부

   연결: F04, F05 / 영향: F04 해결 방식(D04) 선택
