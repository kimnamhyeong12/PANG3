PANG3 모바일 UX 1~6 구현 결과
2026-10-13 / tmap 작업 트리

사용자와 합의한 최종 방향
- 작업 전 / 작업 중 / 작업 후 명칭 유지.
- 모든 상태에서 사진·메모·보고서 수정 가능. 작업 후 자료 수정 금지 전제를 폐기.
- 보고서 수정 때문에 작업 후 상태와 초록색을 자동으로 해제하지 않음.
- 보고서 저장 버튼 유지. 자동 처리는 내용 유실을 막는 기기 내 초안 보관뿐.
- 다음 날 미처리 분류와 이관 수락 후 수동 편입 유지.
- 현장 기록 저장과 복귀 후 HWPX 생성·출력을 분리.

1. 보고서 수정
초록색 마커는 기존 내용을 불러온 작성 화면으로 직접 연결한다. 보고서 목록에서도 상태에 관계없이 작성 화면에 들어갈 수 있다. 서버는 현재 담당자의 작업 후 보고서 수정을 허용한다. 담당자 권한 검사는 유지한다.
기존 보고서를 고칠 때 progressId를 전달하여 같은 보고서를 수정한다. 저장할 때마다 방문 보고서 건수가 늘어나지 않는다. 과거 보고서 수정은 현재 업무 상태·좌표를 변경하지 않는다. 최초 작성자는 유지한다.
변경 내용의 해시를 조회/저장 계약에 포함하고 수정 대상 행을 잠근다. 다른 곳에서 변경된 보고서를 오래된 초안으로 덮어쓰려 하면 저장을 거절하고 작성 내용은 남긴다. DB 컬럼 추가는 없다.

2. 사진 보존
사진은 before/during/after 타입으로 복원한다. 기존 자료는 ‘작업 전|’, ‘작업 중|’, ‘작업 후|’ 접두사도 해석한다.
저장 요청에는 세 슬롯의 keep/upload/delete와 업로드 파일 순서를 명시한다. 기존 사진 참조는 해당 보고서의 같은 단계에 속하는지 서버에서 확인한다. 메모만 수정하면 원격 사진을 유지한다. 새 사진 교체·명시적 삭제는 해당 슬롯에만 반영된다.
새 사진 편집기에 ‘원본 사용’을 추가했다. 기존 사진 편집 취소는 기존 사진을 유지한다.

3. 재방문
workPlan의 날짜별 업무 분류는 변경하지 않았다. 작업 전·작업 중의 상태와 기존 보고서를 유지하며 다음 날 미처리에서 직접 다시 선택한다.
기존 내용이 있는 작성 화면에서 ‘새 방문 보고서 작성’을 선택하면 사진·메모가 비어 있는 별도 보고서 양식으로 전환한다. 기존 보고서는 그대로 남는다. 날짜가 바뀌었다고 기존 보고서를 수정하거나 어제 사진을 오늘 작업 전 사진으로 이동시키지 않는다.

4. 내용 유실 방지
초안을 사용자·업무공간·방문지·기록 종류별로 분리하여 기기에 보관한다. 임의 유효기간을 두지 않는다. 같은 사용자로 다시 접근하면 복구한다. 로그아웃 때 다른 사용자에게 표시하지 않는다.
사진과 편집 완료된 위치도는 앱의 문서 저장 영역에 복사하여 카메라 캐시 정리와 분리한다. 글 입력 후 짧은 대기, 앱 백그라운드 전환, 화면 이탈 때 초안을 기록한다. 화면 이탈이 보관에 실패하면 이동을 막는다. 저장 중 이동과 중복 저장도 막는다.
헤더·Android 뒤로가기·iOS 뒤로가기 제스처·하단 탭·알림 이동은 공통 이동 보호를 거친다. 촬영/앨범을 열기 전에 작성 내용과 사진 단계의 소유 맥락을 보관하고, Android Activity 종료 뒤에는 ImagePicker의 pending result를 해당 맥락에서만 복구한다.
정식 저장 성공 또는 명시적 ‘초안 버리기’ 이후 초안과 전용 사진 폴더를 정리한다. 초안이 정식 기록 저장·업무 상태 변경·HWPX 생성을 대신하지 않는다.
이 보관은 기기 안의 보관이다. 앱 삭제나 기기 변경을 넘어서는 서버 초안 동기화는 구현 범위에 포함하지 않았다. 사진 편집기에서 아직 완료하지 않은 그리기 동작 자체는 원본 사진 복구와 구분한다.

5. 보고서 확인·그룹 이력·출력
선택한 각 보고서의 메모와 단계별 사진을 모두 확인하고 각각 HWPX를 열 수 있다. 선택한 전부의 조회·저장이 확인되면 하나의 HWPX로 모으는 행동도 제공한다. 일부가 누락되거나 조회 실패하면 전체 통합 버튼을 활성화하지 않는다. 선택은 파일 확인 왕복에서 유지한다.
작업 전 상태도 선택할 수 있으며, 실제 저장 기록이 있는지 확인한 뒤 출력한다. 단계명만을 이유로 출력에서 제외하지 않는다.
그룹 보고서 모아보기는 방문지명 + 보고서 건수 목록이다. 방문지를 누르면 날짜·작업자·작업 상태별 기록과 파일 열기/담당자 수정 행동을 제공한다. 파일 열기나 수정에서 돌아오면 방문지 선택과 필터를 유지한다. 작성 기록은 파일이 아직 생성되지 않아도 목록에 포함한다.
방문지 묶음은 주소와 현재 방문지 좌표를 사용하고, 정보가 부족하면 taskId로 분리한다. 이름만 같은 서로 다른 장소를 합치지 않는다. 같은 장소를 다시 등록한 경우 주소·좌표가 일치하면 함께 묶인다. 별도의 영구 장소 ID 도입은 하지 않았다.
현장 저장 API는 HWPX 생성을 기다리지 않는다. 파일 열기에서 서버 생성 API를 호출한다. 보고서를 수정하면 이전 생성 파일의 연결을 무효화하여 다음 출력에 수정 내용이 반영된다.
Python 생성기는 여러 기록을 한 HWPX에 넣고 각 기록의 원래 작성일·상태·메모·사진을 표시한다. 생성 파일명과 임시 사진 작업 폴더를 고유하게 만들어 서로 다른 기록이나 동시에 생성된 파일이 덮어써지지 않도록 했다.
통합 파일 다운로드 식별자는 서버 메모리에 관리한다. 서버 재시작 후에는 화면에서 파일을 다시 생성하면 된다. 개별 보고서 기록은 기존 DB에 유지된다.

6. 다음 행선지
일반 작성 화면에서 저장한 뒤 같은 날·같은 업무공간의 지도에 들어오면 처리한다. 그룹에서 과거 보고서를 선택하여 수정한 흐름에는 끼워 넣지 않는다.
작업 후: 현재 방문지를 제외한 다음 미완료 방문지 경로를 미리 보여준다.
작업 중: 현재 방문지는 노란 상태로 유지하고 ‘다음 방문지’를 누르면 다음 경로를 보여준다.
안내는 기존 ‘안내 시작’ 행동을 눌렀을 때만 시작한다. 다음 후보가 없으면 제안하지 않는다. 기존 방문 순서·복귀 목적지·경로 실패 시 재시도를 사용한다. 길 안내 제공자와 날짜별 업무 편입 정책은 바꾸지 않았다.

검증
- Maven 오프라인 test-compile 성공.
- Java TaskProgressContractTest 성공: 작업 후 수정, 현재 담당자 권한, 오래된 수정 거절, 기존 사진 참조/유지/교체, 과거 기록의 업무 상태 분리.
- Node report-ux-test 성공: 사진 단계 복원, 명시적 삭제, 방문지별 이력 묶음, 사용자/그룹 초안 분리, 캐시와 분리한 사진 보관, 쓰기/삭제 큐 순서, 촬영 단계 소유 맥락 분리.
- 기존 work-plan, visit-order, route-session 검사 성공.
- 수정한 모바일 모듈의 JSX 구문 검사 성공.
- Android Metro/Hermes 번들 export 성공. .env를 로드하지 않고 합성 환경에서 수행했다.
- 합성 자료 통합 HWPX 검사 성공: 두 현장 내용과 서로 다른 사진, 원래 날짜, 메모, 단계, XML 이미지 참조, 고유 파일명을 확인했다. python-hwpx는 기존 프로젝트 의존성을 backend/target의 임시 테스트 경로에 설치하여 사용했다.

검증 한계와 적용
운영 DB·실사용자 자료를 사용한 저장, 실기기 카메라·iOS 제스처·Android Activity 강제 종료, 한컴 앱에서의 최종 인쇄 배치는 직접 검증하지 않았다. HWPX는 실제 생성 파일의 ZIP/XML과 이미지 포함 여부를 확인했다.
로컬 소스 변경이며 서버 배포·앱 배포·운영 데이터 변경은 하지 않았다. 앱과 backend를 함께 반영해야 새 저장·파일 생성 계약이 동작한다. expo-file-system은 이미 설치된 Expo 57 의존성 버전을 직접 의존성으로 선언했다.
