# 핀워크 웹

`npm ci` 후 `npm run dev`로 실행합니다. `npm run build`가 배포용 `dist`를 만듭니다.

## 설정

- `VITE_API_BASE_URL`: API 주소. 개발에서는 기본 `/api` 프록시를 사용합니다.
- `VITE_KAKAO_MAP_KEY`: 브라우저용 카카오 JavaScript 키. 로컬에서 미설정이면 `frontend/.env`의 `EXPO_PUBLIC_KAKAO_JAVASCRIPT_KEY`를 재사용합니다. REST·네이티브 키는 웹에 노출하지 않습니다.
- 카카오 개발자 콘솔에 실제 서비스 도메인을 등록해야 합니다. `localhost:5173`에서 지도 SDK 로딩을 확인했습니다.
- 빌드에 키가 없으면 로그인된 웹이 `/api/client-config`에서 공개 JavaScript 키를 받아옵니다. 메인 배포는 저장소 변수 `VITE_KAKAO_MAP_KEY`를 API 컨테이너의 `KAKAO_JAVASCRIPT_KEY`로 전달합니다.
- 운영 도메인 `pinwork.co.kr`은 EC2 Nginx에서 서비스됩니다. `infra/scripts/deploy-web.sh`가 해당 도메인의 실제 Nginx document root를 확인해 웹 빌드를 반영합니다. 저장소의 별도 Vercel 배포는 운영 도메인의 갱신 경로가 아닙니다.

## 화면과 연동

상단 그룹 선택은 유지하며 왼쪽 메뉴는 대시보드, 지도, 보고서, 그룹, 업무 이관 순서입니다. 개인 그룹도 그룹 목록에 포함됩니다. 운영 문의·시설물 검토는 기존 역할 검사와 공통 레이아웃을 사용합니다.

보고서의 프로젝트 탭은 기존 `/projects` 상세·편집 화면을 그대로 사용합니다. 업무 연결·해제, 저장된 방문지, 완료 기록, 목차 분류, 원본 복원, 보고서 확정·새 버전·이전 버전, HTML/HWPX 내보내기와 기존 권한을 유지합니다.

일반 지도는 로그인 사용자의 방문지만 다룹니다. 주소·장소는 화면에서 바로 검색하며, 등록 도구는 앱의 Ionicons를 재사용합니다. 전체 지도 화면은 고정하고 방문지 목록만 내부에서 스크롤합니다. 목록은 작업 전·중·후 상태만 표시하며 일반 지도에 행정동 경계를 그리지 않습니다.

그룹 목록의 업무현황은 별도 `/groups/status` 화면입니다. 전체·팀원별 지도, 방문지, 작업 상태 집계를 함께 전환합니다. 앱과 동일하게 진행 업무와 오늘 완료한 업무를 집계합니다.

현재 위치는 브라우저 위치 권한을 통해 지도에 표시합니다. 위치가 확인돼야 기존 `/api/routes/order`로 본인 미완료 방문지의 순서를 추천하며, 완료·타인 담당·좌표 없는 방문지는 추천에서 제외합니다. 서버가 거리 기준으로 대체 추천하면 그 안내를 표시합니다.

웹만 변경한 커밋은 운영 API 컨테이너를 다시 만들지 않고 웹만 빌드·배포합니다.

## 웹에서 앱 안내 시작

웹은 `/api/navigation-handoffs`에 현재 담당 방문지와 `car`/`walk`를 저장합니다. 서버는 그룹·담당자·완료 여부·좌표를 검사합니다. 요청은 계정별로 하나이며 10분간 유효합니다. 앱이 시작되거나 활성화되면 요청을 읽고 해당 그룹의 기존 카카오 안내 흐름을 시작합니다. 이전 요청의 확인 처리는 새 요청을 지우지 않습니다.

앱과 웹의 알림 수신 설정은 `/api/notifications/preferences`를 공유합니다. 브라우저·휴대폰의 OS 알림 권한은 기기별입니다.

이 연동을 사용하려면 변경된 백엔드와 웹을 함께 반영하고, 변경된 JavaScript가 포함된 앱을 배포해야 합니다. 현재 설치된 이전 앱에는 수신 코드가 없습니다. 실제 Android 단말에서 차량·도보 SDK 안내를 각각 확인해야 합니다.

새 JPA 테이블: `navigation_handoffs`, `notification_preferences`. 현재 프로젝트의 Hibernate schema update 설정에 따라 생성됩니다.
